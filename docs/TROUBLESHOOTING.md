# Troubleshooting

Run commands in the project root. Check `kubectl config current-context` before changing resources. Never paste tokens, admin passwords, Secret YAML, or private keys into an issue, screenshot, or shared log.

| Problem | Diagnose | Likely cause | Safe fix |
| --- | --- | --- | --- |
| Docker is not running | `docker info` | Docker Desktop/Engine stopped, or account lacks socket access. | Start Docker Desktop or the Linux Docker service; on Linux fix group/socket access and start a new login session. Re-run `scripts/check-prerequisites.sh`. |
| kind cluster creation fails | `kind get clusters`; `docker info`; `kind create cluster --name gitops-demo --config kind-config.yaml --wait 120s` | Docker resources exhausted, blocked downloads, or incompatible versions. | Confirm Internet access and Docker resources; retry only after reading the actual error. Remove a failed cluster only after checking `kind get clusters`; do not delete unrelated clusters. |
| Wrong Kubernetes context | `kubectl config current-context`; `kubectl config get-contexts` | Commands target another cluster. | Run `scripts/setup-cluster.sh` to select `kind-gitops-demo`, then pass `--context kind-gitops-demo` as the scripts do. Never apply cleanup to a context you did not intend. |
| Argo CD pods are unready | `kubectl --context kind-gitops-demo -n argocd get pods`; `kubectl --context kind-gitops-demo -n argocd describe pod POD` | Image pulls, insufficient memory/CPU, or a pending PVC/network failure. | Inspect events and container logs; increase Docker Desktop resources and confirm registry access. Retry the idempotent `scripts/install-argocd.sh` only after resolving the cause. |
| Application is OutOfSync | `kubectl --context kind-gitops-demo -n argocd describe application gitops-demo-dashboard`; compare UI diff with `git show origin/main:k8s/deployment.yaml` | A commit has not synced yet, local drift exists, or Argo cannot fetch the revision. | Confirm correct Git URL/revision and remote push; inspect the diff. Wait for polling or request a sync in the UI. Do not force-edit resources to hide drift. |
| Synced but Degraded | `kubectl --context kind-gitops-demo -n gitops-demo get pods`; `kubectl ... describe pod POD`; `kubectl ... logs deployment/gitops-demo-dashboard` | Sync succeeded, but a Pod/probe/container is unhealthy. | Use pod events and logs; verify tag, Nginx health endpoint, resources, and rollout. Sync state and runtime health are different signals. |
| `ErrImageNeverPull` / `ImagePullBackOff` | `kubectl --context kind-gitops-demo -n gitops-demo describe pod POD`; `docker image ls gitops-demo-dashboard` | Exact image tag is absent from kind, or manifest tag differs from built tag. | Build then load the exact manifest image with `scripts/build-image.sh TAG` and `scripts/load-image.sh TAG`; check `k8s/deployment.yaml`. Do not change to `latest` as a workaround. |
| Wrong repository URL | `kubectl --context kind-gitops-demo -n argocd describe application gitops-demo-dashboard` | Placeholder remains, wrong owner/repository, typo, or pushed branch unavailable. | Export the correct clone URL in `GIT_REPO_URL` and re-run `scripts/deploy-argocd-app.sh`; make sure the project was pushed. The tracked placeholder should stay untouched. |
| Private repository authentication fails | Application conditions in `kubectl ... describe application`; use Argo CD UI repo connection status | Missing/expired credential, wrong URL match, or insufficient permissions. | Add a read-only deploy key/fine-grained token using the secure instructions in `docs/SETUP.md`; never put the credential in Git, URL, or logs. |
| Browser cannot access dashboard | `kubectl --context kind-gitops-demo -n gitops-demo get svc,endpoints,pods`; check terminal running port-forward | Service has no ready endpoint, forwarding stopped, or wrong port/context. | Verify ready Pod and non-empty endpoint; run `kubectl ... port-forward svc/gitops-demo-dashboard 8080:8080` and browse `http://localhost:8080`. |
| Port-forward reports address already in use | `ss -ltnp` (Linux/WSL) or `lsof -nP -iTCP:8080 -sTCP:LISTEN` (macOS) | Another process owns local port. | Stop only the process you identify, or select another local port: `kubectl ... port-forward svc/gitops-demo-dashboard 8088:8080`; use `LOCAL_PORT=8088 scripts/verify-deployment.sh --port-forward`. |
| App changes do not show | `curl -sS http://localhost:8080/version.json`; inspect `git diff`, built tag, and `kubectl ... get deploy ... -o yaml` | Browser cache, stale image, source not included in build, or manifest was never pushed/synced. | Confirm new metadata, build a new non-`latest` tag, load it, update manifest, push, wait for rollout, and hard-refresh. A Git source push alone does not rebuild or load an image. |
| Deleted managed resource was not recreated | `kubectl ... -n argocd get application gitops-demo-dashboard -o yaml` | Application is not synced, resource is outside its source path, or the deletion occurred before Argo observed it. | Confirm auto-sync and self-heal are enabled and the resource is in `k8s/`; inspect Application conditions and wait/request sync. Do not delete shared Argo CD resources. |
| Resource exhaustion | `docker stats`; `kubectl --context kind-gitops-demo describe nodes`; `kubectl ... -n argocd get pods` | Docker Desktop has too little memory/CPU for Kubernetes plus Argo CD. | Increase Docker resources, close unrelated workloads, and retry after nodes recover. Keep the app's requests/limits modest; do not remove resource limits blindly. |

To delete demo resources, use `scripts/cleanup.sh` and read each prompt. Cluster deletion is a separate confirmation; Docker images are retained by default.
